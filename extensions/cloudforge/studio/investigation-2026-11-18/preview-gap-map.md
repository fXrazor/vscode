## Architectural constraints and important findings

- **Preview selection is not yet a robust multi-select model (Confirmed source).** App.selectedId is singular [P11]. React Flow marquee updates transient node selection, but displayNodes reassigns selection from that one ID [P3]. onNodeDragStop commits only the provided node, not a selected group [P4]. A claim of full multi-select parity would be premature. Add persistent selection IDs as presentation state and an atomic moveMany command; test group dragging/undo and frame+child selection.
- **Parentage is visually inferred, not canonical (Confirmed source).** Preview finds a frame containing each resource ID [P3], so overlapping memberships resolve to the first match and nested frames have no semantic containment representation. Source CloudLab has canonical parentId with ancestry and validation [S1,S2].
- **Line kinds must remain distinct (Confirmed source difference).** Semantic reference, explicit depends_on, containment inheritance and visual annotation are different concepts in CloudLab [S3]. Current preview connections cannot represent those distinctions [P1,P2].
- **Annotation collaboration is absent from preview model (Confirmed bounded source finding).** BoardItem supports plain notes/shapes but no comment/thread/author/reply/resolved/presence or viewport-anchored marker entity [P1,P5]. Its current history/persistence cannot be assumed to solve multi-user comments.
- **Provider selection is not saved project configuration (Confirmed source).** Source and catalogue are separate state scopes [P6,S1]. A displayed snapshot version must not be described as backend-selected infrastructure version.
- **The current preview is in-memory (Confirmed source/checkpoint).** Initial sampleArchitecture reducer [P11] has no live persistence adapter; settings and raw Monaco drafts survive certain UI transitions but not reload. Reuse Rust backend boundaries rather than copying browser/localStorage persistence into the shipped product.

## Suggested implementation sequence

1. **Critical foundation:** agree canonical typed graph/value/schema/provider-settings/source-range contracts with the integration owner; retain one graph and one semantic history. Write adapters/tests against the existing Rust protocol without expanding unapproved sensitive operations.
2. **High interaction layer:** quick panels, shape registry, capability-driven selection toolbar, visual connector data/renderers and complete keyboard/focus behavior. Keep registry assets lazy and zoom/drag state isolated.
3. **Critical infrastructure semantics:** domain hierarchy policy, refs/expressions, recursive blocks, provider version/config persistence and module scope. Leverage CloudLab source algorithms as tested reference cases rather than importing its store wholesale.
4. **Critical code workflow:** native Code OSS documents + revision-keyed source map + safe parse/apply/recovery; preserve file assignment, unsupported HCL and user edits.
5. **Medium collaboration/annotations:** entity/world-point/edge-relative anchors, distinct shared annotation data, threaded comments, explicit revisions/conflicts and presence as ephemeral state. Choose synchronization mechanism only after backend/API investigation.
6. **Validation:** browser proofs for create/edit/resize/line style/selection transitions; reducer/domain tests for hierarchy/ref integrity/undo; performance profiles on realistic graphs; accessibility and export fidelity checks.

No implementation or code mutation was performed in this audit.
