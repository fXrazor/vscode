## Interaction sequences

### Resource creation and editing — proposed CloudForge flow

1. Open library on demand; select provider filter/category or search. This changes no architecture configuration.
2. Click-add or drag a resource; show placement decision before drop. Invalid/unknown rules have explicit reasons rather than false green success.
3. Commit creation/parentage/inheritance as one transaction. Select the new resource; Architecture Design renders its provider icon, Configuration renders its editable summary.
4. Open sidebar or focused form. Both bind the same typed draft and recursive schema path. Add blocks only exposes definitions legal for the selected resource/schema.
5. Apply a valid change once; derive reference edges, validation and source projection from that revision. Close returns focus to the selected resource. Undo reverts that operation in either renderer.

This is a proposal. The observed reference form and CloudLab's source support the pattern; a full live create/apply/reload round trip was not performed.

### Whiteboard authoring — mixed observed/proposed

Observed Miro: tool rail → Diagramming shapes → search/category → close; embedded object → Edit → internal toolbar; resize updates attached lines. Observed connector type change participates in outer Undo, whereas tested nested resize did not.

CloudForge proposal: library → add editable primitive → selection toolbar → property popover or direct text edit → one document command. A connector's style/label affects a drawing connector only. Escape closes the innermost surface, then exits text editing, then clears selection; it must not discard a dirty infrastructure draft silently.

### Workspace and code — proposed CloudForge flow

Resource/card selection updates a presentation SelectionModel. A separate explicit reveal action navigates native Code OSS to a fresh trusted range. Source selection can update the resource highlight using origin/revision tokens. Layout changes retain selection and editor drafts, and renderer changes never change theme. Code view can remain open while browsing other resources; whiteboard-only selection retains the last relevant resource code context.

### Keyboard and failure behaviour — acceptance requirements

- Tab reaches library search, selected item, contextual actions and pane separators in a predictable order. Closing a drawer/menu restores its initiating focus.
- Text/number inputs retain their native editing shortcuts. Board Delete/Undo/Space-pan must not intercept typing.
- Pointer cancellation restores pre-gesture geometry; multi-selection moves commit one operation with all selected items, including descendants exactly once.
- Loading schema, unavailable pricing, invalid references, stale source and failed save have distinct states. Counts and status chips must describe actual results.
- Dock/resize constraints protect a usable canvas at narrow widths; hidden panels remain keyboard discoverable. Full free-floating Adobe-style windows are optional, not a prerequisite for useful docking.
