# CloudForge Windows x64 Installer

Use PowerShell 7 on Windows x64. Use the repository's pinned Node and pnpm and run `corepack pnpm install --frozen-lockfile` in this worktree. Install the C++ x64 build prerequisites and the Windows SDK listed in the baseline handoff. Use a short checkout path such as `Z:\CFStage\Code` because some native dependency builds still hit the Windows path limit.

Build `cloudforge-service.exe` from a recorded CloudForge Rust commit using that repository's locked release build. Pass the exact commit and executable SHA-256 to the installer script.

```powershell
.\build\cloudforge\package-win32-x64.ps1 -ServiceExecutable <path-to-cloudforge-service.exe> -ServiceCommit <rust-git-sha> -ServiceSha256 <exe-sha256>
```

The script verifies the service hash and fetches the [JavaScript Debugger 1.140.1 VSIX](https://github.com/microsoft/vscode-js-debug/releases/tag/v1.140.1) when the archive is absent. The upstream extension bundle checks the pinned archive digest and installs its extracted files with the MIT license and third-party notices. JSON Crack (`AykutSarac.jsoncrack-vscode`, MIT, works offline) ships as a built-in JSON graph viewer once it is pinned. Pin it once with `node build/cloudforge/pinOpenVsx.ts` (newest Open VSX version, or `--version <v>`; `--vsix <file>` pins an archive you already have). The script downloads the VSIX to `.build/cloudforge/`, checks its manifest id, version, MIT licence and licence file, and writes the `builtInExtensions` entry with its SHA-256 to `product.json`; commit that change. The installer script then fetches the same archive from Open VSX when it is absent, checks the digest, and checks that the packaged extension carries its MIT licence. Without the entry it warns and packages without JSON Crack. The Windows icon comes from `assets/branding/icon.ico` in the CloudForge Rust repository.

The script packages the desktop in the sibling `VSCode-win32-x64` directory. It then uses the [service stager](../../docs/cloudforge/service-artifact.md) to stage the executable and runtime manifest under `resources/app/cloudforge-service/`; a reused payload's previous service is replaced only if that directory holds nothing else. Immediately before the Inno tasks, the stager's `--verify` mode rechecks the staged folder against the pinned digest, service commit, protocol, and desktop commit. The script then makes the per-user Inno installer at `.build/win32-x64/user-setup/CloudForgeSetup-x64.exe` (when `product.json` declares `applicationName: "cloudforge"`). It prints the installer SHA-256 and the exact desktop and service revisions. `-UseBuiltDesktop` reuses a previously assembled desktop from the current source revision. Pass `-SignCertificateThumbprint` and `-RequireSignedService` for Authenticode-signed builds.

On launch, the packaged **CloudForge** desktop verifies the staged service manifest and SHA-256 digest and negotiates protocol version 1 over private stdio, powering Studio Architecture Canvas, Terraform/OpenTofu language intelligence, offline mirror readiness, guarded draft saves, and local engine validate/plan capture.
